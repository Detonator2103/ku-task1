Задание первой практической работы дисциплины Конфигурационное управление варианта №31 — создание эмулятор оболочки ОС на языке программирования Python.

2. Описание функций и настроек
3. Сборка и запуск тестов
4. Примеры использования

## 1. Общее описание

Программа читает команды пользователя в цикле REPL
(Read-Eval-Print Loop): считывает строку, разбирает её, выполняет команду и
выводит результат. Приглашение к вводу содержит имя VFS и текущий путь.

Проект разрабатывался в пять этапов:

| Этап | Название            | Что реализовано                                         |
|------|---------------------|---------------------------------------------------------|
| 1    | REPL                | Цикл ввода, парсер, `$VAR`, заглушки `ls`, `cd`, `exit` |
| 2    | Конфигурация        | Параметры запуска, стартовый скрипт, отладочный вывод   |
| 3    | VFS                 | Загрузка VFS из XML, команда `vfs-info`                 |
| 4    | Основные команды    | Логика `ls` и `cd`, команды `uname`, `uptime`           |
| 5    | Доп. команды        | Команды `chmod` и `touch` (изменения только в памяти)   |

Используется только стандартная библиотека Python, внешние пакеты не нужны.

### 2.2. Параметры командной строки

| Параметр          | Описание                                      | По умолчанию |
|-------------------|-----------------------------------------------|--------------|
| `--vfs <путь>`    | Путь к физическому расположению XML-файла VFS | пустая VFS   |
| `--script <путь>` | Путь к стартовому скрипту                     | не задан     |

При запуске эмулятор выводит все заданные параметры (отладочный вывод):

```
[DEBUG] vfs    = vfs/deep.xml
[DEBUG] script = scripts/start.txt
```

### 2.3. Стартовый скрипт

Это обычный текстовый файл, в котором одна команда эмулятора на одной строке.

- Пустые строки и строки, начинающиеся с `#`, пропускаются.
- На экране показывается и ввод (`vfs:/> команда`), и вывод команды,
  как будто пользователь вводит её вручную.
- Выполнение **останавливается при первой ошибке** и выводится сообщение
  с номером строки скрипта.
- После успешного выполнения скрипта эмулятор переходит в интерактивный режим
  (если в скрипте нет команды `exit`).

### 2.4. Формат VFS (XML)

Корневой элемент `<vfs>` содержит имя VFS. Внутри — папки `<dir>` и файлы
`<file>`. Бинарные данные хранятся в `base64`.

```xml
<vfs name="myvfs">
  <dir name="home" mode="755">
    <file name="hello.txt" mode="644" encoding="text">Hello!</file>
    <file name="logo.bin" mode="644" encoding="base64">iVBORw0KGgo=</file>
  </dir>
  <file name="readme.txt" mode="644" encoding="text">Корневой файл</file>
</vfs>
```

Весь XML загружается в память в виде дерева объектов. На диск ничего не
записывается, данные VFS не распаковываются.

### 2.5. Команды эмулятора

| Команда                | Этап | Описание                                             |
|------------------------|------|------------------------------------------------------|
| `exit`                 | 1    | Завершает работу эмулятора                           |
| `vfs-info`             | 3    | Выводит имя VFS и хеш SHA-256 её данных              |
| `ls [путь]`            | 4    | Показывает содержимое папки (папки помечены `/`)     |
| `cd [путь]`            | 4    | Меняет текущую папку (`..`, `/`, относительные пути) |
| `uname [-a]`           | 4    | Выводит название ОС (`-a` — подробно)                |
| `uptime`               | 4    | Показывает время работы эмулятора                    |
| `chmod <права> <путь>` | 5    | Меняет права файла/папки (восьмеричное число, `755`) |
| `touch <путь>`         | 5    | Создаёт пустой файл, если его ещё нет                |

Переменные окружения реальной ОС раскрываются в любой команде:
`cd $HOME`, `ls "${USER}"`.

### 2.6. Основные функции и классы

**`emulator.py`**

- `main()` — разбирает параметры, выводит отладочную информацию, загружает VFS,
  запускает скрипт и REPL.
- `parse_line(line)` — делит строку на токены (`shlex.split`) и раскрывает
  переменные окружения (`os.path.expandvars`).
- `run_command(tokens, vfs)` — находит нужную функцию команды и вызывает её.
- `run_script(path, vfs)` — выполняет стартовый скрипт, останавливается на первой ошибке.
- `run_repl(vfs)` — интерактивный цикл ввода.
- `cmd_ls`, `cmd_cd`, `cmd_uname`, `cmd_uptime`, `cmd_chmod`, `cmd_touch`,
  `cmd_vfs_info` — реализации команд.

**`vfs.py`**

- `class Node` — узел дерева (файл или папка): имя, права, данные, дети.
- `class VFS` — хранит корень дерева и текущий путь:
  - `load(path)` — читает XML (`xml.etree.ElementTree`), строит дерево;
  - `find(path)` — находит узел по абсолютному или относительному пути;
  - `get_hash()` — SHA-256 исходных данных XML;
  - `get_prompt()` — строка приглашения.

### 2.7. Обработка ошибок

| Ситуация                   | Сообщение (пример)                           |
|----------------------------|----------------------------------------------|
| Неизвестная команда        | `Ошибка: неизвестная команда '/test'`        |
| Неверные аргументы         | `chmod: неверные аргументы (chmod 755 путь)` |
| Путь не найден             | `cd: нет такого пути: /dir123`               |
| Файл VFS не найден         | `Ошибка загрузки VFS: файл не найден`        |
| Неверный формат XML        | `Ошибка загрузки VFS: неверный формат XML`   |
| Ошибка в стартовом скрипте | `Ошибка в скрипте (строка 3): ...`           |

## 3. Сборка и запуск тестов

### 3.1. Запуск эмулятора

```bash
# без параметров (пустая VFS)
python emulator.py

# с VFS
python emulator.py --vfs vfs/several_files.xml

# с VFS и стартовым скриптом
python emulator.py --vfs vfs/deep.xml --script scripts/stage4_all.txt
```

### 3.3. Запуск тестов

```bash
# Windows
tests\test_stage2.bat     # параметры --vfs и --script, ошибки скрипта
tests\test_stage3.bat     # минимальная VFS, несколько файлов, 3+ уровня
tests\run_all.bat         # все тесты подряд
```

Скрипты со всеми командами этапов лежат в папке `scripts/`:
`stage3_all.txt`, `stage4_all.txt`, `stage5_all.txt`.
`error.txt` специально содержит ошибку для проверки остановки скрипта.

### 3.4. Сохранение результата в репозиторий

```bash
git add .
git commit -m "Add stage 5: chmod and touch commands"
```

## 4. Примеры использования

### 4.1. Интерактивный режим с VFS

```
> python emulator.py --vfs vfs/deep.xml
[DEBUG] vfs    = vfs/deep.xml
[DEBUG] script = (не задан)
deep:/> ls
home/  etc/  readme.txt
deep:/> cd home/user
deep:/home/user> ls
docs/  notes.txt
deep:/home/user> cd ..
deep:/home> cd /
deep:/> vfs-info
Имя: deep
SHA-256: 9f2c1a...e41b
deep:/> exit
```

### 4.2. Команды `uname` и `uptime`

```
deep:/> uname
VFS-OS
deep:/> uname -a
VFS-OS emulator 1.0 python
deep:/> uptime
up 0:05:12
```

### 4.3. Команды `chmod` и `touch`

```
deep:/> touch new.txt
deep:/> ls
home/  etc/  readme.txt  new.txt
deep:/> chmod 755 new.txt
deep:/> chmod 999 new.txt
chmod: неверные аргументы (права должны быть восьмеричным числом)
```

Изменения действуют только в памяти: после перезапуска эмулятора файл
`new.txt` исчезнет, а XML-файл VFS останется нетронутым.

### 4.4. Переменные окружения

```
deep:/> cd $HOME
cd: нет такого пути: C:\Users\Admin
```

### 4.5. Стартовый скрипт

Содержимое `scripts/start.txt`:

```
# приветствие
uname -a
ls
cd home
ls
```

Запуск:

```
> python emulator.py --vfs vfs/deep.xml --script scripts/start.txt
[DEBUG] vfs    = vfs/deep.xml
[DEBUG] script = scripts/start.txt
deep:/> uname -a
VFS-OS emulator 1.0 python
deep:/> ls
home/  etc/  readme.txt
deep:/> cd home
deep:/home> ls
user/
deep:/home>
```

### 4.6. Ошибка в стартовом скрипте

Содержимое `scripts/error.txt`:

```
ls
foobar
ls
```

Результат (третья строка не выполняется):

```
> python emulator.py --vfs vfs/light.xml --script scripts/error.txt
light:/> ls
readme.txt
light:/> test
Ошибка: неизвестная команда 'test'
Ошибка в скрипте (строка 2): выполнение остановлено
```

### 4.7. Ошибки загрузки VFS

```
> python emulator.py --vfs vfs/missing.xml
Ошибка загрузки VFS: файл не найден

> python emulator.py --vfs vfs/broken.xml
Ошибка загрузки VFS: неверный формат XML
```
